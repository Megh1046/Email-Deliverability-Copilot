# AI Engineering Rules

Version: 1.0

These rules apply to every AI model working on this repository.

---

## Repository

Documentation is the source of truth.

Read project context before coding.

Do not ignore existing architecture.

---

## Architecture

Do not rename folders.

Do not change folder hierarchy.

Do not introduce unnecessary abstractions.

One module = one responsibility.

Prefer composition over inheritance.

---

## Development

One task = one feature.

Do not implement future milestones.

Do not "helpfully" add extra functionality.

Keep functions small.

Prefer readability over cleverness.

Use type hints.

---

## Dependencies

Do not introduce new dependencies without justification.

Install only what is required for the current milestone.

---

## Documentation

Update project context after every completed task.

Never rewrite the entire documentation.

Only update relevant sections.

---

## Git

Every task should produce a meaningful commit.

Use Conventional Commits.

---

## Testing

Every completed feature must include a verification method.

Never mark a task complete without verification.

---

## Communication

If repository documentation conflicts with code,

report the conflict.

Do not silently resolve it.

---

## Product Philosophy

Foundation first.

Reliability before automation.

Automation before AI.

AI before polish.

Always optimize for solving the real user problem.
